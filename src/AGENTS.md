# Source implementation guidance

Read the root `AGENTS.md` and `docs/architecture.md` first. Trace changes through the real request path: `main.cpp` selects the checkpoint and backend; `protocol.cpp` prepares and formats requests; `tokenizer.cpp` encodes text; `runtime.cpp` executes the model; `http.cpp` handles transport and queueing. Public C++ types live in `include/laya/`.

## Preserve the request contract

- `agent::prepare` makes one batch row per question. It preserves ordered question and choice objects, formats `choice`, `score`, and `noul` differently, applies the checkpoint's `max_len` and `head_max_len`, neutralizes literal mask tokens, and records option-marker positions. Change the corresponding output formatting in `agent::predict` deliberately when changing preparation.
- English and typed-decisions use byte-level BPE; multilingual uses metaspace BPE with byte fallback. Match the checkpoint tokenizer files and existing fixtures when changing Unicode normalization or added-token handling.
- The public answer contract includes calibrated probabilities, categories, confidence, usage, and four-decimal numeric rounding. Keep option ordering and calibration buckets tied to the loaded checkpoint metadata.

## Preserve execution behavior

- `runtime.cpp` validates checkpoint tensors and owns persistent weights plus reusable encoder and action graphs. The encoder graph depends on batch size, sequence length, option count, and low-precision padding state; the action graph depends on batch size. Reused graphs still need current input tensors and attention masks. Exercise changed shapes, lengths, padding, and repeated calls when modifying graph code.
- CUDA and Vulkan have different mask construction and operator paths. Follow the selected backend end to end; do not assume a CUDA fix applies to Vulkan. Read `docs/precision.md` and `docs/vulkan.md` before editing precision-specific operations or shader dispatch.
- One `agent` is not safe for simultaneous direct calls. `http.cpp` enforces serialized model access through its inference worker while batching whole admitted HTTP calls. Preserve bounded admission, per-call result routing, and error isolation when changing its queue.
- ggml is pinned under `third_party/ggml`. CUDA's modified dispatcher is generated by `CMakeLists.txt` into the build directory. Trace that generated path and its source-version checks before changing custom CUDA operations.

## Verify the affected surface

Use `ctest --test-dir <build-dir> --output-on-failure` for compiled tests. Tokenizer tests require local tokenizer files; model inference requires downloaded checkpoints. For model-facing changes, follow `docs/benchmarking.md` and run matching-precision acceptance over the affected variants and batch shapes. For HTTP changes, run the `http` CTest and use `benchmarks/http_validate.py` when checkpoint-backed transport or dynamic batching behavior changes. A passing kernel or unit test alone does not establish public answer parity.
